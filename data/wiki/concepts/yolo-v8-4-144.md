# YOLO v8.4.144 Release

**버전**: v8.4.144
**릴리스일**: 2026-09-08
**분류**: 모델 아키텍처 변경 없이 신뢰성·수치 안정성·추론 정밀도·배포 워크플로 개선

## 핵심 변경사항

- **모델 YAML 로딩 신뢰성 향상** — `custom26n.yaml`처럼 명시적으로 지정한 파일을 scale-unified
  폴백(`custom26.yaml`)보다 먼저 로드해, 커스텀 모델 정의가 조용히 대체되는 문제 방지.
- **훈련/할당 엣지 케이스 안전성** — 빈 라벨 배치에서도 올바른 타입의 boolean foreground mask를
  반환해 task-aligned assigner의 출력 계약 일관성 유지.
- **저정밀도 CIoU 계산 안정화** — 동일 FP16/BF16 박스에서 NaN 값과 잘못된 gradient를 방지, 저정밀도
  하드웨어에서의 훈련 안정성 개선.
- **`model.to()` 반복 호출 효율화** — 이미 요청된 device/precision에 있는 경우 캐시된 predictor를
  유지해 불필요한 재빌드를 줄이고 반복 추론 설정 시 지연·메모리 사용 절감.
- **Triton FP32 동작 개선** — `quantize=16` 요청 시에도 Triton 클라이언트 텐서를 FP32로 유지해
  의도치 않은 입력 반올림·출력 변환 방지(서버측 모델 정밀도는 유지).
- **시맨틱 세그멘테이션 모자이크 로딩 가속** — 버퍼링된 모자이크 이미지의 시맨틱 마스크를 반복
  디코딩 대신 RAM에 유지, 설정에 따라 약 1.26~1.77배 데이터 로딩 속도 향상.
- **CLI 구성 유연성 개선** — `cfg=<file>` 앞에 전달된 인자 보존, 복사된 설정 파일의 빈 `data` 값이
  태스크 기본 데이터셋으로 올바르게 폴백.
- **OpenVINO/NNCF 호환성 확대** — NNCF 상한 버전 제한 제거로 최신 NNCF 3.x + 최신 PyTorch/OpenVINO
  조합 사용 가능(레거시 제약은 필요한 경우 유지).
- **양자화 문서 보강** — YOLO26 모델의 QAT 대 post-training quantization 비교 결과 문서화. 최소
  모델에는 QAT 효과가 미미하지만 대형 모델에서는 INT8 정확도를 상당히 회복함을 예시로 제시.
- **CI/테스트 인프라 견고화** — CLA 권한 수정, 15GiB 미만 메모리 머신에서 DEEPX export 환경 스킵,
  channels-last 텐서에서의 체크포인트 손상 테스트 정상화.

## 영향

이번 릴리스는 모델 아키텍처 변경 없이 커스텀 YAML·저정밀도(FP16/BF16) 훈련·반복 추론 설정 등
드론 탑재 실시간 검출 파이프라인에서 흔히 마주치는 엣지 케이스의 신뢰성을 높인다. 모자이크 로딩
가속(최대 1.77배)은 세그멘테이션 데이터셋 훈련 처리량을 개선한다.
