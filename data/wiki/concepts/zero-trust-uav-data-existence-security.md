# 지속 검증·존재 허가 기반 제로트러스트 UAV 데이터 존재 보안 프레임워크

한국정보전자통신기술학회 논문지(2026) 게재 논문 초록 기준 요약이다. 원문은 비공개(페이월)다.^[inbox/fetch-2026-11-05-kci-지속-검증과-존재-허가에-기반한-제로트러스트-uav-데이터-존재-보안-프레임워크.md]

## 배경
UAV는 영상, 위치, 센서 데이터를 기체 내부에 저장하므로 재밍, 스푸핑, 강제 착륙, 물리적 포획 이후에도 민감 정보가 노출될 수 있다. 기존 연구는 통신 인증, 접근 통제, 로그 암호화, 원격 삭제에 집중했으며, 데이터가 언제까지 존재할 수 있는지를 장치 내부에서 지속적으로 판단하는 정책 구조는 충분히 다루지 않았다.

## 제안 프레임워크
**핵심 원칙**: 데이터가 존재 허가를 계속 증명하는 동안에만 존속한다.

### 구성 요소
- **환경 증거 (데이터 생존 조건)**: P/G/C 분류 체계
- **장치 허가 (데드맨 스위치)**: H/S/N 분류 체계
- **존재허가 엔진**: 임대(lease)·유예(grace)·우선순위(priority)를 적용해 비존재(S0)부터 파기 완료(S5)까지 상태 전이 제어

### 상태 모델 (S0~S5)
- S0: 비존재(Non-existence)
- S1~S4: 중간 존재 상태(임대/유예/우선순위 적용)
- S5: 파기 완료(Deletion complete)

## 검증
- 설계와 운용의 두 측면에서 정책 타당성 확인
- 가능한 입력 전체에 대한 전수 평가와 확률 모형 분석 수행

## 의의
- 데이터 보호 범위를 접근 시점의 통제에서 **데이터의 존재 허가 관리**로 확장
- 통신 장애 상황에서도 기체 내부에서 데이터 파기 정책을 수행할 수 있는 구조 제시

## 관련
MAVLink 보안은 [[mavlink2-security]], [[mavshield-mavlink-security-cipher]], NC2S 보안 아키텍처는 [[nc2s-secure-c3-uxv]], 제로트러스트 네트워크는 [[nc2s-secure-c3-system]] 참조.
