# YOLO v8.4.160 Release

2026-09-22 릴리스. 새 모델 아키텍처 없이 데이터셋 캐시 무효화, 메모리 사용량, 학습
신뢰성, API 편의성을 개선했다.^[inbox/processed/fetch-2026-09-23-yolo.md]

## 주요 변경사항

- **데이터셋 캐시 무효화(PR #26283)**: 캐시 키가 파일 크기·수정시각을 함께 반영해, 라벨을
  같은 길이로 클래스만 바꿔도 재스캔이 트리거된다. detection/depth/semantic 등 공유 캐시
  사용자에게 적용된다.
- **SAM3 텍스트 프롬프팅 VRAM 절감**: 텍스트 프롬프트를 최대 16개 청크로 처리해 대량
  프롬프트 세트에서 메모리 사용을 줄이고 OOM을 방지한다.
- **OOM 재시도 후 학습 신뢰성 향상**: 배치 크기를 줄여 재시도할 때 옵티마이저·스케줄러
  상태를 재시작하지 않고 보존한다.
- **검증 데이터셋 선택 명확화**: 검증 시 체크포인트에 기록된 데이터셋을 우선 사용하고,
  찾을 수 없으면 경고 후 태스크 기본 데이터셋으로 폴백한다. `data=`로 명시 지정 가능하며,
  depth calibration은 `data`가 필수로 바뀌었다.
- **TensorRT 11 INT8 캘리브레이션 호스트 RAM 절감**: 캘리브레이션 값 변경 없이 소비된
  배치 데이터를 해제하고 in-place 정규화해 피크 호스트 메모리를 줄인다.
- **유틸리티 안전성**: CUDA 기반 결과의 NumPy 변환, NMS가 원본 예측 텐서를 더는 변경하지
  않음, 박스 크롭·경로 변환·단일파일 ZIP 반복 다운로드 처리 개선.

## 영향

라벨을 편집해도 캐시가 조용히 낡은 상태로 남는 위험이 줄어 데이터셋 갱신의 신뢰성이
높아진다(해석). SAM3 청크 처리와 TensorRT INT8 캘리브레이션 메모리 절감은 GPU/호스트
메모리가 제한된 엣지 배포 환경에 특히 유효하다.
