# YOLO v8.4.158 Release

2026-09-21 릴리스. YOLO26 학습 신뢰성, 모델 export 호환성, 데이터 처리, 추론 백엔드,
Ultralytics Platform 워크플로를 전반적으로 개선했다.^[inbox/processed/fetch-2026-09-22-yolo.md]

## 주요 변경사항

- **OOM 복구 후 Mosaic 증강 유지**: 자동 배치 크기 축소로 dataloader를 재생성할 때 Mosaic
  증강이 의도치 않게 다시 켜지던 문제를 고쳤다. 파이프라인 재구성 후 mosaic 종료 로직을 다시
  적용해 증강 상태가 학습 로그·설정과 일치한다.
- **AutoBatch 안정화**: 매우 작은 이미지 크기에서 BatchNorm 때문에 batch-1 프로브가
  실패해도 GPU 메모리 한계로 오인하지 않는다. 작은 이미지 크기용 CUDA 테스트가 추가됐다.
- **데이터 로딩·캐시**: RAM 이미지 캐시를 `spawn`/`forkserver` DataLoader 워커와 더 효율적으로
  공유하고, Linux 워커를 지연 시작해 이미지 디코더 데드락 위험을 줄인다. 데이터셋
  하이퍼파라미터는 transform 전에 복사되어 데이터셋 간 설정 오염을 막고, 디스크 캐시는
  안전 여유를 줄이고 쓰기 실패를 더 안전하게 처리한다.
- **다운로드·데이터셋**: `safe_download()`가 HTTP Range로 중단된 다운로드를 재개하고 인코딩된
  응답과 일시적 서버 오류를 견딘다. 아카이브 이름의 잘못된 파일은 압축 해제된 데이터셋이
  아니라 파일로 반환된다. NDJSON 변환은 유효한 0 아닌 비율이 이미지 0장을 고르는 경우에도
  최소 1장을 유지한다.
- **export 정확도**: 클래스 이름이 없거나 잘못된 export 모델은 999개 기본값 대신 모델 헤드에서
  클래스 수를 추론한다. 구형 PyTorch에서 TorchScript 반복 추론 크래시를 피하고, TensorRT는
  동적 shape 거부나 추론 실행 실패 시 명확한 오류를 낸다.
- **SAM2 비디오 마스크**: 임계값 적용 전에 비중첩 마스크를 강제해, 점수가 가장 높은 객체가
  픽셀을 소유한다. CPU 시맨틱 세그멘테이션 후처리도 클래스 인덱스 선택 개선으로 빨라졌다.
- **Apple 배포**: Core AI 에셋에 모델 설명이 포함되고 Ultralytics iOS SDK·Flutter 플러그인의
  opt-in 경로로 문서화됐다. Core ML이 여전히 기본·권장 형식이며, Core AI는 최신 Apple OS와
  Apple silicon export 환경에 한정된다.
- **Ultralytics Platform**: class-prompted 어노테이션 등이 추가됐다(원문 잘림).

## 영향

드론 탑재 검출 파이프라인 관점에서는 Jetson 등 TensorRT 엣지 배포에서 export 시 클래스
메타데이터·동적 shape 오류가 명확해져 배포 디버깅이 쉬워진다(해석). 학습 쪽 수정은
자동 배치 축소가 일어나는 제한된 GPU 메모리 환경에서 재현성을 높인다.

## 한계
