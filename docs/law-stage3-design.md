# 법령 3단계 설계 — 조문 원문 인용 근거(claim)

> 작성: 2026-11-01 · 상태: **설계안(마스터 승인 대기, 구현 전)** · 관련: `docs/dikw-dynamic-ontology-design.md` §15(1·2단계), `docs/firmware-selection-claims.md` §9(서버 생성 표 패턴), `~/2nd/scripts/fetch-law.py`

## 0. 한 장 요약

| 항목 | 내용 |
|---|---|
| 무엇을 | 법령 질문에 **검증된 조문 원문**을 그대로 인용해 보여 준다(해석·요약·법적 결론은 하지 않는다) |
| 왜 | 1·2단계는 "개정 알림"뿐이라 사용자는 여전히 조문 자체를 못 본다. 운영에서 비행승인·금지구역 질문 대부분이 즉답(verbatim) 경로로 나가는데, 그 즉답의 근거 범위와 시점이 불투명하다 |
| 핵심 원칙 | ①조문 **원문 글자 그대로**만 근거 ②인용 블록은 **코드가 생성**(펌웨어 비교표와 같은 패턴), 모델은 안내 한두 문장 ③시행일·수집일·"법적 자문 아님" 항상 표시 ④기본 off 플래그 |
| 범위(권장) | 6개 법령 중 **드론 관련 조문 약 105건(11만 자)** 에서 마스터가 확정한 60~80건. 별표(212건)·해석 claim·과거 시점 질의는 제외 |
| 일정(추정) | 승인 후 S3-0 1일 → S3-1 2~3일 → S3-2 2~3일 → S3-3 2일(총 약 1.5~2주, 관찰 포함 별도) |
| 결정 필요 | §8 D1~D9 |

## 1. 목표와 비목표

**목표**
- "초경량비행장치 신고는 어디서·누가?", "비행금지구역에서 비행하면?", "특별비행승인 대상은?" 같은 질문에 **해당 조문 원문 + 출처 링크 + 시행일**을 제시한다.
- 조문이 개정되면 자동으로 갱신하고, 갱신이 늦어지면 "최신 아님"을 드러낸다.
- 모델의 법적 환각(없는 조항·틀린 수치·유추한 결론)을 구조적으로 차단한다.

**비목표**
- 법적 자문·비행 가능 여부 판정(기존 "안전·법규 질문 차단" 원칙 유지), 판례·유권해석·행정규칙.
- 과거 시점 법령 조회(질문 시점은 "오늘"만).
- 별표(표·서식) 본문, AI가 쓴 해석·요약 claim(KG 사실로 넣지 않는다).

## 2. 현황과 문제

| 단계 | 상태 | 한계 |
|---|---|---|
| 1단계 | 법령 6건의 개정·시행 **이벤트**를 동향 패널에 표시(운영 활성, 3개 응답 경로) | 알림일 뿐 조문이 아님. 사용자가 법령 내용을 확인하려면 법제처로 나가야 한다 |
| 즉답(verbatim) 경로 | 법령 질문은 `lib/kg-verbatim.ts` 가 **위키 `regulations` 문서(`kr-reg`, 2026-10-20 법제처 수집분 원문 39건에서 만든 위키 7문서)** 의 문장을 골라 보여 준다(모델 미사용) | 안내문은 "문장 그대로"라고 하지만 실제로는 **위키가 정리한 요약 문장**이며(스스로 "법제처 원문과 문자 단위로 대조된 것은 아님"이라 고지), **시행일·수집일이 없고** 조문번호도 일부만 있으며 10/20 이후 자동 갱신되지 않는다. 표본 대조("신고 제외 — 시행령 제24조: 2kg 이하·계류식·연구기관 시험용")는 **현행 시행령 제24조와 일치**(표본 1건) |
| 일반 법령 질문 | 위키 요약·claim 기반, "위키 요약은 단독 근거 아님" 원칙 | 조문 원문 근거가 없어 "자료에 없음"이 많다 |

## 3. 실측 — 법제처 조문 본문 API (2026-11-01, 실키로 6개 법령 조회)

`lawService.do?target=law&MST=<법령일련번호>&type=JSON` 응답 구조(1단계에서 저장한 MST 사용, 키·URL 비출력).

| 발견 | 내용 | 설계 영향 |
|---|---|---|
| 구조 | `법령{개정문, 법령키, 기본정보, 조문{조문단위[]}, 부칙{부칙단위}, 별표{별표단위}, 제개정이유}` | 조문만 파싱, 부칙·별표·개정문은 보존만 |
| 조문단위 | `조문번호`·`조문가지번호`(제N조의M)·`조문여부`(**조문** 또는 **전문**=장·절 제목)·`조문제목`·`조문내용`(조 머리 텍스트)·`항[{항번호, 항내용, 호[{호번호, 호내용, 목[]}]}]`·`조문시행일자`·`조문변경여부`·`조문이동이전/이후`·`조문키`·`조문참고자료` | id 는 `조문번호`+`가지번호`+`항`, 장·절(전문)은 제외 |
| 개정 주석 | 조문내용에 `<개정 2019.8.27, 2021.5.18, …>` 가 **본문에 섞여** 있음 | 원문 인용은 주석 포함본을 보존하고, 표시용은 주석 분리 필드를 둔다(검증은 보존본 기준) |
| 단일 항·호 | 항이 1개이거나 호만 있는 조문은 `항내용`이 없고 `조문내용`에 본문이 있음 | 파서가 항/호 유무별 분기, 시험 필수 |
| 시행일 | 5개 법령은 조문시행일자가 전부 법령 대표 시행일과 같음. **시행령은 `조문시행일자문자열`에 "20260709:제26조제1항제30호, …"** 처럼 일부 항·호의 후속 시행일을 따로 적음 | **부분 시행** 모델 필요 |
| ⚠ 시행일 불일치 | 시행령: 본문 API 대표 시행일 `20260701`, 목록 API(1단계 이벤트 제목) `20260709` | 1단계 패널의 "시행 2026-07-09"는 **후속 부분 시행일**이다. 표기 기준을 대표 시행일로 통일 + 부분 시행 병기 권장(D7) |
| 완전성 | 시행령 조문번호 1~30 연속(가지번호 포함 38단위) → 누락 아님 | 완전성 검사: 조문번호 연속성 점검 시험 |
| 호 표기 | `호번호`("1.")와 `호내용`("1. 행글라이더…")에 **번호가 중복**되어 단순 이어붙이면 "1. 1. 행글라이더"가 된다 | 파서가 번호 접두를 정규화(원문 보존본과 표시본 분리), 시험 필수 |
| 크기 | 조문 본문 합 약 48만 자(UTF-8 1.4MB). 시행규칙은 별표 212건 때문에 응답 4.7MB | 조문만 쓰면 번들 영향 무시 가능, 별표 제외 |
| 삭제 조문 | 시행규칙 2건("삭제") | 표시·검색에서 제외 |

## 4. 설계

### 4.1 원칙
1. **조문 원문만** 근거다. 요약·해석·"~해야 한다는 뜻" 같은 문장은 KG 사실이 아니다.
2. 인용 블록(원문+링크+시행일)은 **코드가 생성**한다. 모델은 "이 조문들이 질문과 어떤 관계인지" 한두 문장과 한계만 쓴다.
3. 모델이 법적 결론을 내지 않는다(기존 규칙 6-2 유지·강화: 발췌에 없는 법적 결론은 "자료에 없음").
4. 모든 응답에 **시행일·수집일·"법적 자문이 아닙니다"** 를 표시한다.

### 4.2 데이터 흐름
```
fetch-law(1단계, 매일 07:30) ── MST 변경 감지 ─┐
                                                ▼
lawService 본문 수집 → 보존(.ua/laws-text/, 해시) → 조문 파서 → 큐레이트 조문 목록(마스터 확정) → law-claims.json
        → build-knowledge-db(검증: 원문 재대조) → 지식 DB → 질의 시 "조문 인용 블록" 생성 → 응답 맨 앞 주입
```
- 보존은 비공개 영역(`~/2nd/.ua/`). **`raw/`는 발행 계층이므로 쓰지 않는다**(1단계 결정과 동일).
- 법령 원문은 저작권 보호 대상이 아니므로(저작권법 제7조) 선정 조문의 원문을 공개 저장소(`law-claims.json`)에 커밋할 수 있다(서비스 이용 조건은 S3-0 에서 재확인, D3).

### 4.3 데이터 모델
| 필드 | 내용 |
|---|---|
| `id` | `LAW-<법령ID>-<조문키>`(항 단위면 `-항N`) |
| `subject` | "항공안전법 제122조(초경량비행장치 신고)" |
| `attribute` / `value` / `quote` | "조문 원문" / **원문 그대로** / 동일(개정 주석 포함 보존본) |
| `law_id`·`mst`·`article`·`effective` | 법령ID·법령일련번호·조문 위치·대표 시행일 |
| `partial_effective` | `조문시행일자문자열` 중 해당 조항 후속 시행일(있으면) |
| `sourceType`/`status`/`topic` | `law` / `verified`(§4.4) / `law-text` |
| `sourceId` | 공개 조문 URL(`law.go.kr/법령/…/제122조`, **형식 미검증 — S3-0 에서 브라우저 확인**) |
| `fetched_at`·`sha256` | 수집 시각·응답 해시 |

### 4.4 검증(기계)
- 파서 산출 텍스트 == 저장 응답의 해당 노드 텍스트(공백 정규화) — 불일치 시 반영 중단.
- 반영 직전 **재조회 대조**(MST 가 바뀌었으면 구버전 claim 을 `superseded` 로 두고 신버전 생성).
- 조문번호 연속성·삭제 조문·가지번호 시험(예: 제125조 → 제125조의2).
- 펌웨어 claim 과 같은 방식: 정본 스크립트가 멱등, 고정 입력(MST)에서 재현 가능.

### 4.5 조문 선정(큐레이트)
- §3 키워드로 후보 ~105건 자동 추출 → **마스터(또는 검토자)가 60~80건 확정**. 항공안전법 제122~131조의2(초경량비행장치)는 장(章) 전체 포함 제안.
- 선정에 없는 조문 질문에는 **"해당 조문은 수록되어 있지 않습니다"** + 법제처 링크로 답한다(추측 금지).
- 후속: 법→령→규칙 **위임 체계** 교차 표시("대통령령으로 정한다" 조문에 시행령 조문 동반) — 1차에서는 같은 법령 묶음 표시까지.

### 4.6 검색·연결
1. **결정론 직접 매칭**: "항공안전법 제125조"처럼 법령명·조문번호가 있으면 그 조문(+ 가지번호).
2. **주제 매칭**: `laws.json` 의 별칭·주제어(비행승인·초경량비행장치·비가시권 …) → 선정 조문(제목 가중치).
3. 기존 `REGULATORY` 판정 재사용. 선택 상한 10건, 법령별로 묶어 표시.

### 4.7 응답 — 서버 생성 "조문 인용 블록"
```
**관련 조문** — 항공안전법 (시행 2026-09-17 · 수집 2026-11-01)
> 제122조(초경량비행장치 신고) ① 초경량비행장치를 사용하여 비행하려는 사람은 … <개정 …>
> 출처: law.go.kr … · 일부 항은 2026-07-09 시행
<sub>조문 원문이며 법적 자문이 아닙니다. 적용 여부는 법제처 원문과 전문가에게 확인하세요.</sub>
```
- 모델 규칙 6-6(안): 인용 블록을 반복·요약하지 않고 ①질문과 조문의 관계 한두 문장(조문 번호 인용) ②한계만. 법적 결론·적용 판단 금지.
- **즉답(verbatim) 경로 정합**: 현재 즉답(위키 요약 문장 기반)을 **조문 원문 블록으로 대체**하고, 위키 요약 문장은 "참고(위키 요약)"로 병기하거나 제외한다(D9). 선정 밖 질문은 기존 위키 요약 즉답이 남으므로 안내문의 "문장 그대로" 표현은 "위키가 정리한 문장"으로 정정한다(소규모 선행 작업).

### 4.8 시점 모델
- 기준은 오늘. `effective ≤ 오늘` 이면 "시행 중", 아니면 "시행 예정".
- 부분 시행은 병기. 수집이 7일 이상 갱신되지 않으면 "최신 아닐 수 있음" 표시.

### 4.9 플래그·롤아웃
`KG_LAW_TEXT=1`(기본 off, 1·2단계와 독립) + 선정 목록 확정 게이트. 롤백은 환경변수 제거.

## 5. 평가
- **골든셋 30문항**(법령 질문 25 + 무관 5): 각 질문의 정답 조문을 검토자가 지정.
- 합격 기준: ①정답 조문 포함률 ≥ 90% ②인용 글자 일치 100% ③법적 결론·유추 서술 0건(전수 열람) ④무관 질문에 조문 블록 0건 ⑤선정 밖 질문은 "미수록" 정확 안내 ⑥기존 25문항 평가 불변.
- 상태 지표가 아니라 **실제 답변 전수 열람**으로 채점(기존 평가 규율).

**다음 후보(S3-2b, 승인 필요)**: ①**닫힌 목록 선택기** — 모델에게 질문과 조문 목록(80건의 번호·제목)만 주고 해당 조문 번호를 고르게 한다. 모델은 조문 텍스트를 쓰지 않고 서버가 번호를 목록과 대조해 검증하므로 환각 불가(잘못 고르면 엉뚱한 조문이 뜨는 위험은 남음). 호출 1회·지연 증가. ②검토자가 지정한 골든셋 30문항으로 규칙을 맞춘 뒤 90% 측정(과적합 위험). ①+②를 병행하면 선택기의 정확도를 골든셋으로 잴 수 있다.

## 13. S3-2b 결과 — 닫힌 목록 선택기 (2026-11-01, 로컬 커밋 d6be337 — 미배포, KG_LAW_TEXT 기본 off)

§12 의 규칙 매칭이 새 질문에서 50% 라 선택기를 추가했다. **조문 텍스트는 여전히 모델이 쓰지 않는다**(§12 의 "모델 미호출"은 "조문 선택에 모델을 쓰지 않는다"였고, 이제 선택에만 모델을 쓴다).

| 구성 | 내용 |
|---|---|
| `lib/law-select.ts` | 모델에게 질문 + 80건 목록(`[L01] 항공안전법 제2조 정의` 형식, **제목만**)을 주고 `{"codes":["L07"]}` 만 출력하게 한다(chat 프로필·temperature 0·출력 48토큰·10초 제한). 응답은 서버가 파싱·검증: 목록 밖 코드·조문 번호·잘린 JSON·비 JSON 은 **선택 실패**로 처리해 규칙 매칭으로 대체. 최대 5건, 중복 제거 |
