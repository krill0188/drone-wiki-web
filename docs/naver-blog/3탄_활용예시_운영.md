# 드론위키: Codex-LB + Hermes Agent + Telegram 설치 가이드 (3탄) — 활용 예시 5가지와 안전한 운영 방법

> 1탄(Codex-LB), 2탄(Hermes·Telegram)까지 설치가 끝났다는 전제입니다.

---

## 11. 세 가지 설치 완료 후 활용 예시 5가지

### 예시 1 — 프로젝트 상태 확인

Telegram에서:

```
genius-tft 프로젝트의 Git 상태와 최근 변경 파일을 요약해줘.
파일은 수정하지 마.
```

확인 내용:

```
git status
git diff --stat
최근 커밋
변경 파일
```

---

### 예시 2 — 테스트와 빌드 실행

```
genius-tft에서 다음 명령을 실행해줘.

npm test
npx tsc --noEmit
npm run build

코드는 수정하지 말고 각 결과를 알려줘.
```

이 작업은 Codex-LB와 Hermes 연결이 정상인지 확인하는 좋은 첫 테스트입니다.

---

### 예시 3 — 코드 수정 전 계획만 받기

```
genius-tft의 Testbed 화면을 점검해줘.
현재 문제와 수정 예정 파일만 정리하고 아직 파일은 수정하지 마.
```

계획 확인 후:

```
계획대로 수정해줘.
수정 후 npm test와 npx tsc --noEmit을 실행해줘.
```

초기에는 항상:

```
계획
→ 사용자 승인
→ 수정
→ 테스트
```

순서로 사용합니다.

---

### 예시 4 — 공식 문서 조사

```
ArduCopter 4.6.3의 EKF3 고도 설정을 공식 ArduPilot 문서만 사용해서 조사해줘.
파라미터 이름, 값, 의미, 출처 URL을 정리해줘.
확인되지 않은 내용은 추정하지 마.
```

Hermes가 웹 검색과 문서 수집을 담당하고 Codex-LB는 조사 결과 정리와 설명에 사용될 수 있습니다.

---

### 예시 5 — 정기 테스트 알림

```
매일 오전 9시에 genius-tft의 npm test와 TypeScript 검사를 실행해줘.
성공·실패 여부를 Telegram으로 알려줘.
코드 수정과 배포는 하지 마.
```

운영 구조:

```
Hermes Cron
→ 테스트 실행
→ 결과 확인
→ Telegram 보고
```

처음에는 자동 수정이나 자동 배포를 포함하지 않는 것이 좋습니다.

## 12. Genius-TFT에 적용할 때의 권장 운영 단계

```
Codex-LB 설치
→ ChatGPT 계정 1개 연결
→ API 요청 확인
→ Hermes 설치
→ Hermes를 Codex-LB에 연결
→ Telegram 연결
→ 읽기 전용 테스트
→ 코드 수정 승인 방식 사용
→ Testbed 검증
→ 실제 데이터 연결
→ Shadow Mode
→ Paper Trading
```

처음부터 다음 기능은 사용하지 않습니다.

```
실제 매수·매도
Live 브로커 연결
자동 주문
자동 배포
자동 Git push
민감 파일 삭제
강제 reset
```

초기 Telegram 봇 권한은 다음처럼 제한합니다.

```
허용 사용자: 본인 1명
사용 공간: 개인 대화
코드 수정: 승인 후
실제 주문: 비활성화
배포: 비활성화
```

## 13. 중지·재시작 명령

### Codex-LB

macOS/Windows 공통:

```
docker stop codex-lb
docker start codex-lb
docker restart codex-lb
docker logs codex-lb
```

삭제:

```
docker rm codex-lb
```

데이터까지 삭제하는 명령은 사용하지 마세요.

```
docker volume rm codex-lb-data
```

이 명령은 Codex-LB 계정·사용량·암호화 데이터가 삭제될 수 있습니다.

### Hermes

```
hermes gateway status
hermes gateway stop
hermes gateway start
```
