## 1. 측정 사실 (VERIFIED)

### 1.1 질문 36개 운영 실측 (수정 전)

| 유형 | answered | unverified | 거절 | 게이트 |
|---|---|---|---|---|
| 개념 | 3 | 0 | 3 | 0 |
| 선택 | 0 | 2 | 3 | 1 |
| 추론 | 2 | 2 | 2 | 0 |
| 문제해결 | 1 | 0 | 5 | 0 |
| 규정 | 2 | 0 | 4 | 0 |
| 제품 | 3 | 2 | 1 | 0 |
| **합계** | 11 | 6 | **18** | 1 |

한계: 질문 세트를 제가 만들었으므로 실제 사용자 분포와 같다고 주장할 수 없다.

### 1.2 거절 원인 분해

| 계열 | 내용 | 해당(거절 18건 중) |
|---|---|---|
| F1 한국어 어미 오판 | `refuseMissingCore`가 활용형 표면형의 문서빈도(≤15)를 "희귀한 핵심어"로 판정. 어미 목록이 표면형 개별 등록(`회사야·회사인가·회사인가요…`)이라 `의미야`의 `야`, `쓰이나요`, `좋을까요` 등이 누락 | 약 11건 |
| F2 한영 어휘 격차 | 위키는 한·영 혼합. `쿼드콥터` 0문서(quadrotor는 다수), `브러시리스` 3문서(brushless 다수). `KO_EN`은 손으로 쓴 약 100항목 | 일부(F1과 중첩) |
| F3 진짜 위키 공백 | Here3, 드론 보험 등 | 약 3~4건 |

### 1.3 수정 후 효과 (계획기 판정 + 실제 모델 답변)

- 거절 18 → 7/36. 남은 7건: 설계 게이트 마찰(FPV 입문), 추중비, 쏠림 원인, 영상 전송 끊김, 야간 비행, 드론 보험, Here3.
- 70문항(운영 점검 25 + 프로브 36 + 대조군 9) 변경 전/후: 거절→답변 12, **답변→거절 0**, 거절 유지 19, 답변 유지 39(근거 종류 동일).
- 의도 밖 변화 1건: "바람 10m/s일 때 쿼드콥터는 안전하게 비행할 수 있어?" — `쿼드콥터` 어휘 추가로 거절이 풀림. 실제 답변 2회 모두 "근거에 없다"고 답하고 안전 단정을 하지 않음(안전장치 작동 확인).

### 1.4 거절이 풀린 12건의 실제 유용성 (전수 열람)

| 판정 | 건수 | 질문 |
|---|---|---|
| ✅ 도움이 됨 | **5** | PID 튜닝, SLAM, 군집 통신, GPS 불안정, 조종자 자격증(조문 문장 인용) |
| △ 부분적 | 4 | 농업 모터(권고 불가·1개 사양만), EKF 에러(원인 없음·관련 파라미터만), 야간 센서(논문 1편), 수출 규제(미국·중국 위주로 취지와 거리) |
| ❌ 정직하지만 무정보 | 3 | KV 의미, 모터 과열 해결, 바람 10m/s |

### 1.5 구조 결함 — `answered`의 의미 (VERIFIED)

"근거에 없다"는 답변도 상태가 `answered`(UI에서 "검증됨")다. 성공 지표가 부풀려지고 사용자는 무정보 답변을 검증된 답변으로 읽는다. 추론 질문("배터리 5000→10000mAh면 비행시간 두 배?")은 `answered`인데 내용이 **무관한 배터리 사양표 2개**였다.

## 2. 냉정한 재판단 — 권고안 각각

### 2.1 제 이전 보고의 과장

1. "거절 50% → 19%"는 **상태 지표**다. 유용성 기준 이득은 36문항 중 +5건.
2. 실사용 규모를 모른다. 질문 세트는 자체 제작이다.
3. 원인 비율("거절의 60%")은 정확한 집계가 아닌 근사다.

### 2.2 권고안별 판정

| # | 방안 | 근거의 질 | 판정 |
|---|---|---|---|
| **A** 거절 수정 배포 | 강함: 70문항 회귀 0, 대조군 유지, 실모델 11건 위반 0 | **즉시 추진. 이견 없음** |
| **B** 일반 지식 계층 | 강함(무정보 3건+부분 4건이 지식 공백 때문). 그러나 **마스터 원칙(그래프만 사실 근거) 완화** + 안전 민감 질문 위험 | **추진하되 가드레일 선확정**(§3). 안전·법규 질문은 제외 |
| **C** 추론 계산기 | 약함: 추론 6문항 중 2건이 이미 답변, 수요 미확인, 구현 무거움 | **후순위** |
| **D** 미답변 백로그 → 지식 보강 | 로직은 옳으나 **실사용 로그가 거의 없어 현재 입력 데이터가 없음** | **트래픽이 생긴 뒤**로 이동 |
| **E** 어휘 다리 자동화 | 중간: `쿼드콥터` 하나가 질문 1건을 바꿈, F2는 수동 확장의 한계 | B 다음 |
| **F** 게이트 완화·스트리밍 재작성 | 증거는 1~2건이나 비용이 매우 작고 마찰이 명백 | **C보다 앞** |

### 2.3 단계 0 신설 — 계측

방향을 정하는 데이터가 없다. 비용이 작은 순서로:

1. `answered` 안에서 **"근거에 없음" 응답을 구분**하는 지표 추가(`limitations`의 "찾지 못했습니다" 패턴 → `coverage: full|partial|none`). 상태 값은 바꾸지 않고 메타만 추가해 기존 UI·집계에 영향 없음.
2. 수집 동의 단계의 **이탈 측정**(동의 화면 노출 대비 동의 수). 이탈이 크면 Q&A 품질 개선의 효과가 사용자에게 닿지 못한다.
3. Vercel 서버 요청 수(`/api/chat` 호출·403 비율) 확인 — 현재 도구 권한으로는 불가, 대시보드 확인 필요.

### 2.4 재정렬된 순서

| 순위 | 항목 | 비고 |
|---|---|---|
| 0 | 계측(coverage 메타, 동의 이탈) | 작음 |
| 1 | **A 배포** | 롤백 기준 사전 확정 |
| 2 | **B 일반 지식 계층** | 플래그·가드레일·평가 |
| 3 | F 게이트 완화·스트리밍 재작성 | 작음 |
| 4 | E 어휘 다리 자동화 | 중간 |
| 5 | C 추론 계산기 | 수요 확인 후 |
| 6 | D 백로그→지식 보강 | 트래픽 이후 |

**A와 B는 원래 권고 순과 같다.** 이견은 F를 C 앞으로, D를 맨 뒤로 옮긴 것뿐이며 A·B 착수에는 영향이 없다.

## 3. B 설계 — 라벨된 일반 공학 설명 계층

### 3.1 원칙

- **근거 기반 본문은 변경하지 않는다.** B는 본문 뒤에 붙는 **별도 섹션**이며 별도 모델 호출로 만든다(본문의 인용·검증·시험을 건드리지 않는다).
- 항상 라벨: `🔮 일반 공학 설명 — 위키·지식그래프 근거 아님 · 재확인 필요`. 신뢰도 "낮음" 고정. 인용 표기([P]·[C]) 없음.
- **사실 근거로 쓰지 않는다.** 10/19 원칙(답변의 사실은 지식그래프·검증 claim·규칙·설계 엔진에서만)은 본문에서 그대로 유지된다. B는 "근거가 없는 부분을 일반 원리로 설명해 보되 근거가 아님을 명시"하는 별도 층이다.

### 3.2 발동 조건

모두 만족할 때만:

1. 질문 유형이 **개념·원리·원인 후보·점검 순서**(정의형·진단형)다.
2. 근거 기반 본문이 해당 관점을 **"찾지 못했습니다"**로 처리했거나(`coverage: partial|none`), 계획기가 주제어 미충족으로 거절했으나 **드론 도메인 질문임이 확인**된 경우. (위키 밖 대조군 — 김치찌개·양자·비트코인 등 — 은 도메인 확인에서 걸러 계속 거절한다.)
3. **안전·법규 차단 목록에 해당하지 않는다**(아래).

### 3.3 차단 목록 (B 비활성, 기존 동작 유지)

| 범주 | 예 | 이유 |
|---|---|---|
| 비행 가능·안전 한계 판단 | "바람 10m/s에서 안전한가", "이 조건에서 날려도 되나" | 틀리면 사고. 근거 없는 안전 단정 금지 |
| 법규·허가·자격·보험·수출 | 조종자 자격증, 비행 승인, 보험 | 위키가 조문 문장 인용 경로를 이미 가짐(`kg-verbatim`). 일반 지식으로 대체 금지 |
| 제품 사양·모델 비교·가격 | "T-Motor 스펙", "Pixhawk 6X vs 6C" | 사양은 지식그래프에서만 |
| 수치·한계값을 묻는 질문 | "추력비 얼마면 충분", "몇 분 비행" | 수치 금지 원칙 |

### 3.4 출력 제약 (코드가 검증)

| 제약 | 검증 |
|---|---|
| **숫자·단위·임계값 금지** | 기존 `unsupportedNumbers`를 B 구간에 적용: 목록 번호 외 숫자가 하나라도 있으면 B 섹션 전체 폐기 |
| 제품명·모델명·제조사명 금지 | 영문+숫자 토큰, 컨텍스트 밖 고유명 정규식 → 폐기 |
| 단정 표현 금지("반드시 안전", "문제없습니다", "보장") | 금지어 목록 → 폐기 |
| 분량 상한 | 항목 최대 6개, 항목당 1~2문장 |
| 형식 | 정의/원리/원인 후보/점검 순서 중에서만 소제목 |

검증 실패 시 B 섹션을 **통째로 생략**하고 기존 응답을 그대로 낸다(조용한 강등 아님 — 메타에 `generalTier: "rejected"` 기록).

### 3.5 구현 형태

- 플래그 `KG_GENERAL=1`(기본 off), 독립 모듈 `lib/general-tier.ts`(발동 판정·프롬프트·검증), `route.ts`와 `kg-answer.ts`에서 본문 생성 뒤 조건부 호출.
- 별도 모델 호출이므로 발동 시 지연·비용이 늘어난다(발동률은 평가로 측정). 타임아웃 시 B만 생략.
- 메타: `answerMeta.generalTier: "shown" | "rejected" | "skipped"`, UI는 접이식 패널이 아니라 **본문과 시각적으로 구분되는 별도 블록**(라벨 상시 표시).
- 롤백: 플래그 off 한 줄.

### 3.6 평가 계획 (배포 전 합격 기준)

## 7. B 구현 결과와 평가 (2026-10-27, VERIFIED)

### 7.1 평가가 바꾼 설계

처음 설계(§3)는 정의·원인·점검 순서를 허용했다. **실모델 평가(E4)에서 통과한 25건을 전수 열람한 결과 사실 오류·깨진 용어 5건(20%)** 이라 범위를 좁혔다.

| 발견 | 조치 |
|---|---|
| 정의형 오류 집중(프로펠러 피치·오프보드 제어·추력·ESC 정의) | **정의형 제외** — 위키 기초 개념 문서 보강으로 해결 |
| '점검 순서'의 허위·무의미 절차(존재하지 않는 메뉴 이름, 전원 끈 상태에서 자석 반응 관찰) | **점검 순서·절차형 제외**, 원인 후보 나열만 |
| 깨진 단어(`바ométric`·`프롭eller`) | 검증기에 혼합 문자·영어 단어 혼용 폐기 |
| 숫자 폐기 10건 중 7건이 목록 번호 | 번호는 불릿으로 정규화 후 검증 |
| 리포 배터리 부풀음 같은 안전 치명 질문 | 차단 목록에 발화·화재·부풀음·추락·사고 추가 |
| 계획기 주제어 누락 거절에 기대면 정상 질문 20개 중 14개 스킵 | 강한 드론 어휘로 도메인 확인(일반 하드웨어 단어 단독 불가) |
